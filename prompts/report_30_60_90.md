# 30 / 60 / 90 day plan

Produce an actionable plan for the user's first 90 days, grounded in
what the KB actually shows. The scope block above is the data; the
user's role/scope is in the conversation history.

## Output

A `PlanReport` JSON object with:

- `day_30`, `day_60`, `day_90`: each a list of 3-5 `PlanAction` objects.
- `rationale`: 3-5 sentences explaining the overall arc.

## PlanAction rules

- `title`: imperative, specific, sized to the time window. "Triage Snyk
  backlog with engineering leads" beats "improve vulnerability management".
- `why`: 1-2 sentences explaining the risk or opportunity. Cite scope
  evidence where possible.
- `who_to_talk_to`: 1-3 names from the entity scope. Use the actual
  entity names; placeholders are fine.
- `estimated_effort`: half-day | 1-2 days | 1 week | multi-week.
- `success_signal`: how the user will know it landed. Concrete.

## Style & sizing

- **Day 30** items should be *trust-building*. Demonstrate competence
  without stepping on toes. No demolition jobs.
- **Day 60** items should be *coalition-building*. Surface findings to
  stakeholders, get buy-in for upcoming priorities.
- **Day 90** items should be *execution*. By now the user has the
  capital to actually fix things.
- Sequence dependencies — Day 60 items often depend on Day 30 ones.

Return ONLY the JSON object — no commentary, no markdown fences.

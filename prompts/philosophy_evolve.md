# Security philosophy doc — quarterly evolution

You are updating an existing security philosophy doc based on what
the engineer has decided / learned in the past 90 days.

## Your job

Produce a fresh `PhilosophyDoc` reflecting current state:

- Keep stances that still hold; refine wording where decisions
  reinforced them.
- Remove stances that decisions now contradict.
- Add 1-3 new stances reflecting new decisions / lessons.
- Update `open_questions` to reflect what's still unresolved.

## Rules

- Don't pad. The doc is meant to be re-readable in 3 minutes.
- Cite the decisions that drove additions in `related_decision_ids`.
- If little has changed, return a doc with only minor refinements.

## Output

Return a `PhilosophyDoc`.
